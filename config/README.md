# Central configuration

Copy `config.example.json` to ignored `config.json` and edit only the local copy.
Run `python scripts/installer.py --config config/config.json config validate`.
The example passes structural validation but deliberately fails deployment readiness.
No password, customer secret key, private key, token, or Kubernetes credential belongs
in this JSON. Unknown keys, duplicate JSON keys, invalid types, unsupported backends,
and inline credential fields fail closed.

`terraform` maps directly to the variables in `terraform/variables.tf`. The installer
requires the core example fields; certificate, S3 group policy, tags, logging retention,
and backup policy fields are optional. Use `TF_VAR_mysql_admin_password` for the
provisioning password. Other `TF_VAR_*` variables and Terraform CLI environment
overrides are rejected so central configuration remains authoritative. Windows
environment-name normalization is handled before invoking Terraform.

`platform` contains the wrapper's supported Helm inputs: MySQL, S3-compatible object
storage, Temporal, UI access, immutable service images, and MySQL Router. Set database
host/port to `127.0.0.1:6446`; put the actual remote database DNS name in
`platform.mysqlRouter.host`. The schema database name must remain `michelangelo`.
Autonomous, PostgreSQL, direct OCI resource principals for the artifact client,
public LoadBalancer/Ingress access, and Cadence are unsupported by this wrapper.
Use the dedicated S3 customer secret key exception with bucket-scoped IAM.

Bundled Temporal is the default. The wrapper derives its chart values rather than
accepting arbitrary nested overrides: both stores use `mysql8`, existing password
Secret references, CA trust, and mandatory hostname verification. Its frontend
endpoint must equal `<release>-temporal-frontend:7233`. Schema setup creates
`temporal` and `temporal_visibility`; the upstream namespace job registers the
configured Temporal domain. External Temporal is also supported, with an explicit
`workflow_namespace_registered` attestation. The Go workflow clients connect over
in-cluster gRPC; this wrapper does not provide workflow TLS or authentication.

`deployment` sets the source path, release, namespace, exact Kubernetes context/API
server, timeout, and explicit MVP exceptions. `mysql_mvp_approved` and
`static_object_storage_credentials_approved` must reflect an actual approval;
`router_tls_verified` requires successful runtime transport testing, including cold
authentication and negative certificate tests. These booleans are attestations,
not evidence generated by validation. `enable_mutations=false` blocks apply/install.
Set it before generating the artifacts you intend to apply; configuration changes
invalidate saved review receipts.

For optional `install --sync-secrets`, provide these process environment variables:

| Variable | Purpose |
| --- | --- |
| `MYSQL_PASSWORD` | Password for the chart's schema/runtime user |
| `AWS_ACCESS_KEY_ID` | Dedicated OCI S3 customer key identifier |
| `AWS_SECRET_ACCESS_KEY` | Dedicated OCI S3 customer secret |
| `MYSQL_CA_FILE` | Public CA certificate bundle for the remote database |
| `MYSQL_ROUTER_AUTH_CERT_FILE` | Dedicated Router RSA certificate file |
| `MYSQL_ROUTER_AUTH_KEY_FILE` | Dedicated Router RSA private key file |

Router authentication material must be distinct from the database server's private
key; the remote server key never enters Kubernetes. The CA Secret contains public
certificates only. Secrets are streamed through stdin to `kubectl apply --server-side`;
they are absent from command arguments, generated Helm values, and local manifests.
Alternatively, provision the four referenced Secrets out of band. Certificate expiry,
matching keys, SAN identity, and least-privilege database grants require operator checks.

The source/image versions are immutable in `upstream.lock.json` and the installer.
The wrapper pins release commit `37852aace4dd9f9658c11c19c56d19692ac5d2c4`
after inspection of main commit `d717c2b1f8d2512cb6859d5560d54960471dc89f` showed
chart differences from the published 0.11.0 images. Arbitrary source revisions are
not accepted as config overrides.

## Platform and deployment field reference

Terraform field defaults and validations are documented in
[the infrastructure table](../docs/infrastructure.md#configuration-contract) and
[`variables.tf`](../terraform/variables.tf). The dev example overrides automatic
backup retention to 1 day; Terraform's default is 7 days. Actual final backup
retention must be inspected separately after database deletion.

| Field | Meaning / supported value |
| --- | --- |
| `schema_version` | Configuration schema; currently integer `1` |
| `platform.metadataStorage.driver` | Fixed `mysql`; PostgreSQL/Oracle SQL are unqualified |
| `platform.metadataStorage.host`, `port` | Fixed loopback `127.0.0.1:6446` for the verified Router path |
| `platform.metadataStorage.database` | Fixed `michelangelo` to match the upstream schema |
| `platform.metadataStorage.user` | Schema-scoped application user, distinct from provisioning administrator |
| `platform.metadataStorage.existingSecret` | Kubernetes Secret containing application password; no inline password |
| `platform.objectStorage.auth` | Fixed `s3_static`, the approved compatibility exception |
| `platform.objectStorage.endpoint` | OCI S3 compatibility hostname without scheme; use actual Terraform output |
| `platform.objectStorage.secure`, `region` | HTTPS must be true; region matches the bucket/deployment |
| `platform.objectStorage.bucket` | Exact artifact bucket name, matching Terraform |
| `platform.objectStorage.existingSecret` | Secret with AWS access-key/secret-key fields |
| `platform.workflow.engine`, `mode` | `temporal`; mode `bundled` or independently managed `external` |
| `platform.workflow.endpoint` | `<release>-temporal-frontend:7233` when bundled; reachable host:port when external |
| `platform.workflow.domain` | Temporal namespace; `default` in the example, not an OCI identity domain |
| `platform.mysqlRouter.image` | Immutable verified amd64 Router digest |
| `platform.mysqlRouter.host`, `port` | Actual remote MySQL DNS identity and SQL port; never substitute the loopback endpoint here |
| `platform.mysqlRouter.caSecret`, `caKey` | CA Secret and public CA data key, normally `ca.pem` |
| `platform.mysqlRouter.authSecret` | Separate frontend Router RSA certificate/key Secret |
| `platform.mysqlRouter.python` | Absolute interpreter path with pinned PyYAML 6.0.3; separate from OCI CLI environment |
| `platform.ui.apiBaseUrl` | Local Envoy URL on 8081; `http://127.0.0.1:8081` in the access guide |
| `platform.images` | Four fixed upstream service image digests; source upgrades require qualification, not arbitrary config overrides |
| `deployment.upstream_path` | Pinned source checkout path relative to repo root, or absolute path |
| `deployment.namespace`, `release` | Kubernetes namespace and Helm release; drive generated service/resource names; Secret names use explicit references |
| `deployment.kube_context`, `kube_api_server` | Exact verified target; Bastion path uses isolated kubeconfig and loopback API on 16443 |
| `deployment.timeout_seconds` | Helm install/rollout timeout, 900 seconds in example |
| `deployment.mysql_mvp_approved` | Attestation accepting OCI MySQL for this MVP |
| `deployment.static_object_storage_credentials_approved` | Attestation accepting scoped S3 customer-secret-key use |
| `deployment.router_tls_verified` | Attestation that the required runtime transport qualification passed |
| `deployment.workflow_namespace_registered` | Required attestation for external Temporal namespace registration |
| `deployment.enable_mutations` | Master apply/install/session/bootstrap guard; CLI confirmations are still required |

See [deployment](../docs/deployment.md) for when to update endpoint-dependent fields
and [access](../docs/access.md) for local port/context configuration. Example flags
remain false so copying the file alone cannot deploy or assert transport evidence.
